# KubeStack — SDLC record (v0.1)

One document per release covering requirements → design → build → test → release → operate.
Rules referenced as **R#** are the numbered rules in `CLAUDE.md`.

## 1. Requirements

### Functional
| ID | Requirement |
|----|-------------|
| F1 | List all managed clusters with tier, upgradeOwner, Kubernetes version and readiness |
| F2 | Create an RKE2 cluster from a catalogued version; default ingress Traefik (R7) |
| F3 | Upgrade a cluster's Kubernetes version, only when tier/upgradeOwner allow it (R5, R6) |
| F4 | Refuse upgrades that skip a minor, downgrade, lack a <24h etcd snapshot or have unready nodes |
| F5 | Delete a provisioned cluster with explicit confirmation |
| F6 | Show an audit trail of every lifecycle operation (R16) |
| F7 | Show *why* an operation is unavailable, using the server's reason (R6) |
| F8 | Portal sign-in/sign-out via the organisation's OIDC provider |
| F9 | Join nodes to a provisioned cluster without KubeStack ever handling the join token (R15) |
| F10 | Import (attach) an existing cluster; disconnect it later without destroying it |
| F11 | Take and list etcd snapshots; restore one (destructive: typed confirmation + idempotency key) |
| F12 | List nodes with roles/readiness; remove a node, never the last etcd or control-plane node |
| F13 | People reach provisioned clusters directly with their own IdP identity (R16); KubeStack never handles their credentials |

### Non-functional
| ID | Requirement |
|----|-------------|
| N1 | Rancher reached only via CRDs; no Steve/Norman; Rancher code only in `internal/engine/rancher/` (R1–R3) |
| N2 | No public-internet calls at runtime; versions from the bundled catalog, generated by `make catalog` from the pinned Rancher image's RKE2 metadata (R13, R14) |
| N3 | No secrets in logs/responses/fixtures (R15) |
| N4 | OIDC authentication; mutations require the admin group |
| N5 | Destructive API calls require an `Idempotency-Key`; replays return the stored result (R17) |
| N6 | Audit "attempt" written before any engine call; if it can't be written the op is refused |
| N7 | Only allowed licenses ship (R11) |
| N8 | Runs as non-root, read-only root FS, least-privilege RBAC on Rancher's local cluster |

## 2. Design
```
Portal (React/TS) ──/api/v1──▶ server ──▶ domain.Allowed / upgrade.Check
                                  │                 │
                                  ├──▶ store (Postgres | memory): audit, idempotency
                                  └──▶ engine.Engine ──▶ rancher (dynamic client, CRDs) | fake
```
- `domain.Cluster.Allowed(op)` is the single capability gate; the API returns its result per
  operation so the UI never re-derives rules.
- Upgrade pre-flight lives in `internal/upgrade` and runs server-side only.
- Rancher field semantics: see `docs/adr/0001-headless-engine-adapter.md`; verified by e2e.
- API contract: `api/openapi.yaml`.

## 5. Release
1. `make ci` green; e2e green for every version in `deploy/compat.yaml`; `docs/acceptance.md` passed on real VMs.
2. Update `compliance/THIRD-PARTY.md` if dependencies changed; add ADR if behaviour changed.
3. Bump `deploy/helm/kubestack/Chart.yaml` `version`/`appVersion`; tag `vX.Y.Z` (Conventional Commits).
4. Push tag `vX.Y.Z`. `release.yml` builds the image, pushes it to GHCR, signs it with cosign (keyless,
   GitHub OIDC), attaches the SPDX SBOM as an attestation and publishes `kubestack-airgap-vX.Y.Z.tar.gz`.
   Locally: `make airgap-bundle TAG=vX.Y.Z REGISTRY=<registry>`.
5. Verify: `cosign verify ghcr.io/<owner>/kubestack/kubestack-api:vX.Y.Z --certificate-identity-regexp 'github.com/<owner>/KubeStack' --certificate-oidc-issuer https://token.actions.githubusercontent.com`.

**Air-gapped install:** copy the bundle across, `tar xzf`, `./mirror.sh <mirror>` (verifies SHA256SUMS, loads and
pushes the unmodified image), then `helm install` the bundled chart with `image.registry=<mirror>`.
KubeStack's installer accepts no third-party terms on the operator's behalf (R8); community Rancher's own
install is the operator's step.

## 6. Operate
**Install** (into Rancher's local cluster, in-cluster identity):
```bash
kubectl create ns kubestack
kubectl -n kubestack create secret generic kubestack-db --from-literal=DATABASE_URL='postgres://…'
helm install kubestack deploy/helm/kubestack -n kubestack \
  --set image.registry=<mirror> --set databaseSecret=kubestack-db \
  --set oidc.issuer=<issuer> --set oidc.clientID=<client> --set adminGroup=<group>
```
Portal sign-in: register `https://<host>/auth/callback` with the IdP and set `oidc.redirectURL`
(plus `oidc.clientSecretSecret` for a confidential client). Alternatively leave it empty and front the
portal with an OIDC-aware proxy that forwards `Authorization: Bearer <id_token>`. See ADR 0002.

**Runbook**
| Symptom | Meaning / action |
|---------|------------------|
| 503 "audit trail unavailable; operation refused" | Postgres down — restore DB; no lifecycle op ran |
| 412 "pre-flight checks failed" | Expected guard: take an etcd snapshot / fix nodes / upgrade one minor at a time |
| 409 "upgrade not permitted" | Tier or upgradeOwner forbids it (e.g. hosted → upgrade in the cloud console) |
| 409 "…still in progress" | Same Idempotency-Key in flight; wait, don't retry with a new key |
| 502 "lifecycle engine error" | Rancher API unreachable/rejected; see API logs (`slog`, no secrets) |
| Cluster stuck deleting; finalizer `auth.cattle.io/capi-resources-cleanup`; Rancher logs `no matching controller owner ref` | Rancher never created the CAPI Cluster (CAPI webhook was down at create time, rancher/rancher#40535). Check `cattle-capi-system/capi-controller-manager`; escalate to Rancher ops — KubeStack never strips finalizers |
| 409 "cluster changed concurrently, retry" on snapshot/restore | Someone else changed the cluster spec at the same moment; retry |
| Restore requested but nothing happens | Rancher acts only when etcd nodes are up; check the cluster's conditions in Rancher. Restore keeps version and config (`restoreRKEConfig: none`) |
| Audit row with `attempt` but no `success`/`failure` | API crashed mid-op — check cluster state in Rancher, then record outcome |

## 7. Known gaps (backlog)
- Direct access: a real kubectl login is not covered by e2e (no nodes).
- Upgrading imported clusters needs etcd snapshot visibility for them (pre-flight can't be bypassed); refused with a reason.
  Kept for GA (2026-11-21). Possible later route: RKE2/K3s record snapshots in-cluster as `ETCDSnapshotFile` (unverified).
- KubeStack-owned upgrades (System Upgrade Controller): dropped from GA by the product owner (2026-11-21). No cluster
  gets `upgradeOwner: kubestack` (provisioned = rancher, attached = rancher or none), so the path would be unreachable.
- `kubestack-controller` + CRDs: deferred by the product owner until there is a GitOps user (2026-11-18).
- SBOM covers the Go binary and base image; portal npm packages are listed in `compliance/THIRD-PARTY.md`
  (bundled JS is not detected by syft).

### v0.2.0 air-gapped install — 2026-11-21: FAIL, fixed for v0.2.1
Published `kubestack-airgap-v0.2.0.tar.gz` on a Docker `--internal` network (no route out): bundle `mirror.sh` into a
private registry (from its own daemon on that network), community Rancher v2.15.3 with bundled charts and preloaded
images, Dex as the IdP, `helm install` of the bundled chart with `image.registry=<mirror>`.
1. **ImagePullBackOff**: `mirror.sh` kept the GHCR owner path (`<mirror>/maddydevel/kubestack/kubestack-api`), the chart
   pulls `<mirror>/kubestack/kubestack-api`; the chart's default registry (`""` = Docker Hub) did not exist either.
   Fix: `images.txt` lists the mirror path, `mirror.sh` uses it; default registry is the published `ghcr.io/maddydevel`.
2. **CreateContainerConfigError**: `runAsNonRoot` with the image's named user `nonroot`, which kubelet cannot verify.
   Fix: `runAsUser/runAsGroup: 65532`.
`make helm-lint` now renders the chart and fails on either regression. With both fixes the documented steps work
unchanged: pod Running offline, `/healthz` ok, API 401 without a token, signed-in user lists clusters and versions
through the chart's service account.

### Findings fixed because of e2e against real Rancher
1. **Stale release catalog**: Rancher v2.15.3 supports RKE2 v1.34–v1.36 (default v1.36.5); the bundled
   catalog was v1.32–v1.34. Refreshed from Rancher's own release list; e2e now fails if the catalog lacks
   Rancher's default version.
2. **Deprecated API**: CAPI `Machine` v1beta1 is deprecated in v2.15; adapter moved to v1beta2 (storage version).
3. `rke2-default-version` setting omits the `v` prefix that the webhook requires (test-side normalisation).
4. Rancher's single-container install needs its extension API registered in time; e2e sets
   `AGGREGATION_REGISTRATION_TIMEOUT=10m` and runs with bundled charts + preloaded images
   (`hack/e2e-images/<version>.txt`), so it needs no network inside the container.
5. `compat.yaml` placeholder (v2.12) replaced with the current community stable, v2.15.3.

6. **Intermittent e2e hang (2 of 5 runs)**: deleting a cluster created while Rancher's CAPI webhook was
   still starting hung forever (see runbook). e2e now waits for `capi-controller-manager` and asserts the
   CAPI Cluster exists before deleting. Verified 3/3 consecutive passes on 2026-11-18 (89s, 46s, 45s).

### Environment notes (this workstation, not product issues)
- Kiri's network was broken (no outbound NAT/DNS, published ports reset, BuildKit "not found"). Cause: Docker's
  `docker0` and Kiri's `kiri0` both used 172.17.0.0/16, so traffic to Kiri containers was routed into the dead
  `docker0`; and Docker's FORWARD DROP policy blocked `kiri0`. Fixed 2026-11-21: `/etc/docker/daemon.json` moves Docker
  to 172.31.0.0/16 (pools 172.30.0.0/16), and `/etc/systemd/system/kiri.service.d/nat.conf` adds DOCKER-USER accept
  rules and a MASQUERADE for 172.17.0.0/16. Builds, pulls and published ports work in Kiri again.
- `kiri machine create` makes containers on the host kernel (no systemd as PID 1, no `/lib/modules`), so they
  cannot run RKE2; use KVM VMs for node tests.
